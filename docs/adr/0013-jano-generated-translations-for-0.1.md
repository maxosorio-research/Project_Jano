# ADR 0013 — Jano-generated translations for 0.1

Status: Accepted

## Context

The reader originally anticipated that a user could supply a translated PDF,
Markdown file, or text file. Discovery could pair those files by name, but Jano
did not have a reliable contract for turning arbitrary translated content into
target segments or for establishing correspondence with the original.

The active local pipeline already produces source and target segments with the
same stable per-run IDs. That is sufficient to exercise the central bilingual
reader without prematurely choosing a heuristic external-alignment algorithm.

## Decision

Jano 0.1 supports translations generated by Jano's user-initiated local
pipeline. The import dialog accepts the original PDF only. Generated target
segments and alignments are persisted according to ADR 0012.

External translated PDFs, Markdown files, and text files are not supported
inputs for the 0.1 reader. Existing files discovered in a project are preserved
and may remain visible as project data, but Jano does not claim that they are
normalized, aligned, or synchronizable. The UI must explain this limitation
instead of offering a processing action that would overwrite or reinterpret the
external file.

Supporting external translations is a post-0.1 feature. It requires an explicit
ingestion and provenance model, target segmentation, correspondence confidence,
unmatched-content handling, and tests for non-1:1 alignment.

## Consequences

- The 0.1 exit test has one authoritative translation path.
- Generated segment IDs provide deterministic structural correspondence.
- The import flow is smaller and cannot imply unsupported external alignment.
- User-supplied translation files are never deleted or overwritten to make them
  fit the Jano-generated pipeline.
- Heuristic alignment remains an architectural extension rather than a hidden
  prerequisite for the first release candidate.
